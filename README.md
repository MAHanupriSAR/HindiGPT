# HindiGPT 🇮🇳

A from-scratch GPT-style Transformer built entirely in PyTorch, trained on a Hindi corpus and fine-tuned for Hindi sentiment classification. The project implements every component of a modern large language model pipeline — tokenisation, dataset construction, the Transformer architecture, language model pre-training, and downstream classification — without relying on any pre-built model library.

## 1. Project Overview

HindiGPT is a two-stage NLP system for the Hindi language:

| Stage | What it does |
|-------|-------------|
| **Pre-training** | Trains a GPT decoder on raw Hindi text to learn language structure via next-token prediction. |
| **Fine-tuning** | Loads the pre-trained backbone weights and attaches a classification head to categorise Hindi movie reviews by viewer experience (negative / neutral / positive). |

The entire model is implemented from first principles — no Hugging Face `transformers`, no pre-trained weights from the internet.

## 3. Architecture

The model follows the standard **GPT decoder-only Transformer** pattern: token embeddings + positional embeddings → stacked Transformer blocks → layer norm. Task-specific heads are attached on top of this shared backbone.

### 3.1 Core Backbone — `MiniGPTBase`

**File:** `src/model.py`

```
Input token IDs  →  Token Embedding (vocab_size × embed_dim)
                 +  Positional Embedding (max_seq_len × embed_dim)
                 →  [TransformerBlock] × num_layers
                 →  LayerNorm
                 →  Output features  (batch, seq_len, embed_dim)
```

| Parameter | Default | Description |
|-----------|---------|-------------|
| `vocab_size` | 5000 | Total BPE vocabulary size |
| `embed_dim` | 256 | Dimension of every token / position vector |
| `num_heads` | 8 | Number of attention heads |
| `hidden_dim` | 512 | Inner dimension of the feed-forward sublayer |
| `num_layers` | 4 | Number of stacked Transformer blocks |
| `max_seq_len` | 128 | Maximum sequence length (context window) |

Both the token embedding and the positional embedding are learnable `nn.Embedding` tables. Positional IDs are created on-the-fly via `torch.arange` and moved to the correct device automatically.

---

### 3.2 Causal Multi-Head Attention

**Class:** `CausalMultiHeadAttention` in `src/model.py`

Implements the standard scaled dot-product attention with a **causal (lower-triangular) mask** so each token can only attend to itself and earlier tokens — the same mechanism used in GPT.

**Step-by-step forward pass:**

1. Project input `x` to Query, Key, and Value tensors via three independent `nn.Linear` layers (`q_proj`, `k_proj`, `v_proj`), each mapping `embed_dim → embed_dim`.
2. Reshape and transpose to shape `(batch, num_heads, seq_len, head_dim)` where `head_dim = embed_dim // num_heads` (= 32 for the defaults).
3. Compute raw attention scores: `scores = Q @ K^T / sqrt(head_dim)`.
4. Apply the causal mask: positions in the upper triangle (future tokens) are filled with `-inf` before softmax, ensuring they receive zero attention weight.
5. Compute `attn_weights = softmax(scores, dim=-1)`.
6. Compute the weighted sum of values: `out = attn_weights @ V`.
7. Reshape back to `(batch, seq_len, embed_dim)` and project through `out_proj`.

---

### 3.3 Feed-Forward Network

**Class:** `FeedForward` in `src/model.py`

A two-layer MLP with ReLU activation:

```
Linear(embed_dim → hidden_dim) → ReLU → Linear(hidden_dim → embed_dim)
```

This is the standard position-wise feed-forward network from *Attention Is All You Need*. With the defaults, it expands the representation from 256 to 512 dimensions and then back.

---

### 3.4 Transformer Block

**Class:** `TransformerBlock` in `src/model.py`

Wraps one attention sublayer and one feed-forward sublayer with **pre-norm** residual connections (layer norm is applied before each sublayer, matching the GPT-2 convention):

```
x = x + CausalMultiHeadAttention(LayerNorm(x))
x = x + FeedForward(LayerNorm(x))
```

---

### 3.5 Task Heads — `GPTLanguageModel` & `GPTClassifier`

**File:** `src/heads.py`

Both classes accept the same hyperparameters as `MiniGPTBase` and share the identical backbone.

#### `GPTLanguageModel`

Used during **pre-training**.

```
MiniGPTBase  →  lm_head: Linear(embed_dim → vocab_size)
```

The `lm_head` projects each position's feature vector to a score over the full vocabulary. Logits at every position are used to compute cross-entropy loss against the next-token targets.

**Text generation** (`generate` method):
- Accepts a tensor of seed token IDs (`start_tokens`) and `max_new_tokens`.
- At each step: clip context to `max_seq_len` if needed → forward pass → take logits at the last position → softmax → `argmax` → append to sequence.
- Uses greedy decoding (argmax, not sampling).

#### `GPTClassifier`

Used during **fine-tuning**.

```
MiniGPTBase  →  classifier_head: Linear(embed_dim → num_classes=3)
```

Only the **last token's feature vector** is fed to the classifier head — a standard approach for causal models (the final token has attended to the entire sequence). Outputs logits over 3 classes: `0` (negative), `1` (neutral), `2` (positive).

## 4. Tokeniser

**File:** `src/tokeniser.py`  
**Class:** `HindiTokenizer`

Wraps the HuggingFace `tokenizers` library's **Byte-Pair Encoding (BPE)** implementation to train a subword tokeniser specifically on the Hindi training corpus.

| Method | Input | Output | Description |
|--------|-------|--------|-------------|
| `train(text_list, vocab_size=5000)` | List of Hindi strings | — | Trains BPE from scratch using a `BpeTrainer`. |
| `encode(text)` | A single Hindi string | List of integers | Returns a list of integer token IDs. |
| `decode(token_ids)` | List of integers | Hindi string | Converts IDs back to a Unicode string. |
| `save(file_path)` | Path string | — | Serialises the trained tokeniser to a JSON file. |
| `load(file_path)` | Path string | — | Loads a previously saved tokeniser. |

**Special tokens** registered during training:

| Token | ID | Purpose |
|-------|----|---------|
| `[UNK]` | 0 | Out-of-vocabulary subwords |
| `[PAD]` | 1 | Padding (used in classification) |
| `[BOS]` | 2 | Beginning of sequence (reserved) |
| `[EOS]` | 3 | End of sequence (reserved) |

**Pre-tokeniser:** `Whitespace` — splits on whitespace before BPE merges, which works well for Hindi since words are separated by spaces.

## 5. Dataset Utilities

**File:** `src/dataset_utils.py`

### 5.1 Language Modelling Data

#### `load_and_split_corpus(file_path, train_ratio=0.9)`

Reads the merged Hindi corpus text file line by line, strips blank lines, and splits into train (90%) and validation (10%) lists of strings.

#### `LanguageModelingDataset`

A `torch.utils.data.Dataset` for **autoregressive next-token prediction**.

- Flattens all token IDs for a split into one long 1-D list.
- `__len__` returns `len(tokens) - seq_length` valid starting positions.
- `__getitem__(idx)` grabs the chunk `tokens[idx : idx + seq_length + 1]` and returns:
  - `x = chunk[:-1]` — the input sequence (length `seq_length`)
  - `y = chunk[1:]`  — the target sequence (each token shifted one step right)

This gives the model a training signal at every position simultaneously (teacher forcing). For example with `seq_length=3` and tokens `[10, 20, 30, 40]`:
- Input  `x = [10, 20, 30]`
- Target `y = [20, 30, 40]`

---

### 5.2 Text Classification Data

#### `load_classification_data(file_path, train_ratio=0.8)`

Reads the CSV, performs an 80/20 deterministic train/validation split using `iloc` (no shuffling — reproducible).

#### `TextClassificationDataset`

A `torch.utils.data.Dataset` for sentiment classification.

- Reads `text` and `experience` columns from the dataframe.
- Tokenises each review with the trained `HindiTokenizer`.
- **Truncation:** clips reviews longer than `max_length` tokens.
- **Padding:** pads shorter reviews with token ID `1` (`[PAD]`) to reach exactly `max_length`.
- Returns `(x, y)` where `x` is a `torch.long` tensor of shape `(max_length,)` and `y` is a scalar label `{0, 1, 2}`.

## 7. Pre-processing — Merging the Corpus

**File:** `src/merge_files.py`

Before language model training can begin, the many individual corpus `.txt` files must be merged into one:

```bash
python src/merge_files.py
```

**What it does:**
1. `glob`s all `*.txt` files in `data/raw/hindi_corpus/train/`.
2. Sorts them **numerically** by filename (so `2.txt` comes before `10.txt`).
3. Concatenates non-empty content, writing each file's content followed by a newline.
4. Skips and counts empty files.
5. Logs progress every 1000 files.
6. Writes the result to `data/raw/hindi_corpus/merged_train.txt`.

The hardcoded paths can be changed at the bottom of the script:

```python
INPUT_FOLDER = "data/raw/hindi_corpus/train"
OUTPUT_FILE  = "data/raw/hindi_corpus/merged_train.txt"
```

## 8. Training — Language Model

**File:** `src/train_lm.py`  
**Entry point:** `run_language_modeling()`

### Pipeline

```
1. Load & split corpus    (load_and_split_corpus)
2. Train BPE tokeniser    (HindiTokenizer.train)
3. Encode all splits      (tokenizer.encode for each line → flat token list)
4. Create Datasets        (LanguageModelingDataset for train & val)
5. Create DataLoaders     (batch_size=32, train shuffled)
6. Initialise model       (GPTLanguageModel)
7. Loss: CrossEntropyLoss | Optimiser: Adam (lr=0.001)
8. Train for 5 epochs     (train_epoch + evaluate each epoch)
9. Save model weights     → gpt_language_model.pth
10. Generate sample text  → generated_output.txt
```

### `train_epoch`

- Sets model to `model.train()`.
- Iterates batches with a `tqdm` progress bar.
- For each batch: zero grad → forward → reshape logits to `(batch*seq_len, vocab_size)` → compute loss → backward → step.
- Returns average loss over the epoch.

### `evaluate`

- Sets model to `model.eval()` with `torch.no_grad()`.
- Computes average validation loss and **perplexity** (`exp(avg_loss)`).

### `generate_hindi_text`

- Encodes a seed string (default: `"यह फिल्म"` — *"This film"*).
- Calls `model.generate(start_tokens, max_new_tokens=50, max_seq_len=128)`.
- Decodes the resulting token IDs back to Hindi text.

### Console output per epoch

```
Epoch 1 | Train Loss: X.XXXX | Val Loss: X.XXXX | Val Perplexity: XX.XXXX
```

## 9. Training — Text Classifier

**File:** `src/train_classifier.py`  
**Entry point:** `run_classification()`

### Pipeline

```
1. Load corpus & train tokeniser  (same as LM training — tokeniser is re-trained)
2. Load classification CSV         (load_classification_data → 80/20 split)
3. Create Datasets                 (TextClassificationDataset for train & val)
4. Create DataLoaders              (batch_size=32, train shuffled)
5. Initialise GPTClassifier
6. Load pre-trained backbone       (gpt_language_model.pth → filter backbone.* keys)
7. Loss: CrossEntropyLoss | Optimiser: Adam (lr=0.001)
8. Train for 5 epochs              (train_epoch + evaluate each epoch)
9. Save classifier weights         → gpt_classifier.pth
```

### Transfer Learning

Weights are loaded from the pre-trained language model with careful key filtering:

```python
pretrained_dict = torch.load("gpt_language_model.pth", map_location=device)
model_dict = model.state_dict()
# Only load keys that exist in the classifier AND come from the shared backbone
pretrained_dict = {k: v for k, v in pretrained_dict.items()
                   if k in model_dict and k.startswith("backbone")}
model_dict.update(pretrained_dict)
model.load_state_dict(model_dict)
```

This ensures the `lm_head` weights from pre-training are discarded and the `classifier_head` is randomly initialised, while all `backbone.*` (embeddings + Transformer blocks + norm) are warm-started.

## 13. Usage

All scripts are designed to be run from the **project root** directory (`HindiGPT/`).

### Step 1 — Merge the corpus (one-time pre-processing)

```bash
python src/merge_files.py
```

Produces `data/raw/hindi_corpus/merged_train.txt`.

### Step 2 — Pre-train the language model

```bash
python src/train_lm.py
```

- Trains the BPE tokeniser on the corpus.
- Trains the GPT language model for 5 epochs.
- Saves weights to `gpt_language_model.pth`.
- Generates and saves sample Hindi text to `generated_output.txt`.

### Step 3 — Fine-tune the sentiment classifier

```bash
python src/train_classifier.py
```

- Requires `gpt_language_model.pth` to exist (run Step 2 first).
- Loads pre-trained backbone, attaches classifier head.
- Fine-tunes for 5 epochs on the movie review dataset.
- Saves weights to `gpt_classifier.pth`.

## 14. Design Decisions & Notes

### Why decoder-only (GPT-style) for classification?
GPT-style models use the **last token's hidden state** for classification — causal attention ensures this position has attended to all previous tokens, capturing a full-sequence representation. This is a standard and effective approach for causal LMs repurposed as classifiers.

### Why BPE for Hindi?
Hindi uses the Devanagari script. Character-level tokenisation would be expensive; word-level would suffer from a huge vocabulary and OOV issues. **BPE** finds a middle ground: frequent subword units are merged, giving the model a compact vocabulary (5000 tokens) that still represents rare words compositionally.

### Pre-norm vs post-norm
The `TransformerBlock` applies **LayerNorm before** each sublayer (pre-norm), matching GPT-2. Pre-norm is generally more stable during training than post-norm (original Transformer paper).

### Greedy decoding
Text generation uses `argmax` (greedy decoding), which is deterministic but tends to produce repetitive output. Temperature sampling or top-k / top-p sampling would improve output diversity and fluency.

### Causal mask implementation
The mask is constructed fresh every forward pass using `torch.tril`. For production, it would be more efficient to register it as a buffer (`self.register_buffer`) so it moves to the correct device automatically and is not recomputed each call.

### `.gitignore`
The `data/raw/hindi_corpus/` folder is excluded from version control because the raw corpus files can be very large. The classification CSV is tracked (6 MB).
